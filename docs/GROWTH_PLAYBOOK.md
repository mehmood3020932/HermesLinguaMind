# Hermes Growth Playbook

The goal is not to manufacture stars. The goal is to create a product people genuinely want to share, then make contribution and discovery frictionless.

## The viral product loop

1. User chooses native language + target language.
2. AI companion introduces itself in the user's language.
3. User completes a short speaking challenge.
4. Hermes gives a visible improvement/correction.
5. User gets a shareable progress card.
6. Friend opens the demo.
7. Friend can try the same 60-second conversation without an account where the deployment supports it.

## GitHub star loop

- README must communicate the product in 15 seconds.
- Put a 60–90 second demo near the top.
- Keep Quick Start honest and short.
- Maintain `good first issue`, `help wanted`, and language labels.
- Publish a monthly release/changelog.
- Welcome first-time contributors with small, mergeable tasks.
- Use Discussions for roadmap and community questions.
- Never use fake stars, fake users, fake testimonials or automated engagement.

## Content engine

Publish 3–5 short demos per week:

- “I built an AI teacher that explains English in Urdu.”
- “Speak English for 60 seconds; Hermes corrects you.”
- “What happens when an open-source AI tutor remembers your mistakes?”
- “Adding a new language pack to an open-source tutor.”
- “CPU avatar vs real avatar inference.”

Every video should point to one action: try the demo, star the repo, add a language, or join the community.

## Launch sequence

### Before launch
- [ ] Clean CI baseline
- [ ] One-command local setup
- [ ] 60–90 second demo
- [ ] Screenshots/GIFs
- [ ] License inventory
- [ ] Security review
- [ ] Issue templates
- [ ] Contributor guide

### Launch week
- [ ] GitHub release
- [ ] Product landing page
- [ ] Demo video
- [ ] Hacker/community posts where relevant
- [ ] Invite language communities to contribute packs
- [ ] Founder story post

### After launch
- Weekly changelog
- Monthly roadmap update
- Contributor recognition
- Public bug-fix progress
- Publish real metrics when they exist

## Anti-patterns
- Buying stars
- Astroturfing reviews
- Claiming “production ready” before validation
- Claiming a generated avatar is live inference when it is not
- Bundling model weights without license review
- Tracking users without clear privacy disclosure
