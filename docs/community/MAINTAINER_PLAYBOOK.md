# Maintainer Playbook

## PR policy

Prefer small, reviewable PRs. Require CI before merge. For user-facing features, include screenshots or a short recording and tests where practical.

## Labels

- `good first issue`
- `help wanted`
- `area:flutter`
- `area:backend`
- `area:ai`
- `area:avatar`
- `area:language`
- `area:docs`
- `area:devops`
- `priority:high`
- `priority:medium`
- `priority:low`

## Release cadence

- Patch: bug/security fixes
- Minor: backwards-compatible features
- Major: breaking API/schema changes

## Contributor recognition

Keep a human-maintained contributor list or generated credits page. Recognize code, documentation, translations, curriculum, testing, design and community support—not only commits.
